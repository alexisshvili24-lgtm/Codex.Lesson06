# Git Support — руководство пользователя

Git Support отвечает на вопросы по Git с опорой на вашу базу знаний. В ответе можно открыть исходный фрагмент и посмотреть, почему он был выбран. Если необходимых сведений недостаточно, чат сообщает, какая часть вопроса осталась без подтверждения.

Для первого запуска, настройки ключа и переноса на сервер используйте [руководство разработчика](developer-guide.md). Технический путь от загрузки до ответа описан в [руководстве по реализации RAG](rag-architecture.md).

## Первый сеанс

1. Откройте приложение. На компьютере с обычной установкой адрес — [127.0.0.1:8025](http://127.0.0.1:8025/). Для удалённого доступа используйте адрес, который сообщил человек, развернувший приложение.
2. На вкладке «Настройки» проверьте подключение RouterAI и доступ к обеим моделям. Если ключ не задан, введите его и сохраните настройки.
3. На вкладке «База знаний» загрузите документ. Нажмите «Подготовить и индексировать» и дождитесь окончания. До индексации чат не ищет в новом материале.
4. На вкладке «Чат» нажмите «Новая беседа». Задайте вопрос, ответ на который вы знаете по этому документу. Откройте одну из ссылок в ответе и сравните её с утверждением чата.
5. Для проверки разных типов вопросов используйте вкладку «Тесты RAG».

Для первого набора материалов подойдут [Pro Git на русском](https://git-scm.com/book/ru/v2), его [исходные файлы](https://github.com/progit/progit2-ru) и [справка git status](https://git-scm.com/docs/git-status). Загружайте файлы или ZIP с текстовыми исходниками. Поле URL служит для указания происхождения документа и не запускает скачивание страницы.

## Вкладка «Чат»

Слева расположен список бесед. «Новая беседа» открывает пустой чат, а первый успешно обработанный вопрос становится названием беседы. Выбор беседы открывает сохранённые вопросы и ответы. В «Архиве вопросов» доступны прежние независимые вопросы, сохранённые до появления бесед. Архив можно просматривать, а для продолжения темы из архива нужно открыть новую беседу.

Справа в переписке ваши сообщения показываются в облачках справа, ответы помощника — слева. Введите вопрос в поле «Вопрос о Git» и нажмите «Отправить». Для самостоятельной темы создайте новую беседу. Для уточнения вроде «А как это сделать без потери правок?» продолжайте текущую. Местоимения и ссылки на предыдущие реплики помощник уточняет по истории этой беседы.

Под ответом отображается одно из состояний:

| Состояние | Как его читать |
| --- | --- |
| Полный ответ | Модель считает, что предоставленные фрагменты покрывают вопрос. Проверьте ссылки, если вывод важен для вашей работы. |
| Частичный ответ | Подтверждена только часть. Поле «Недостающая информация» показывает, что осталось без подтверждения. |
| Ответ не найден | Найденных сведений недостаточно для ответа. Возможно, нужного документа нет в активном индексе или подходящий фрагмент остался вне итоговой подборки. |

Ссылки `[S1]`–`[S10]` открывают модальное окно с текстом чанка, названием документа, путём к файлу, разделом и другими доступными метаданными. URL источника отображается, если он был указан при загрузке. Нумерация начинается заново в каждом ответе. Снимок источника привязан к моменту запроса, поэтому старый ответ остаётся проверяемым после замены исходного файла.

Под перепиской находится свёрнутый блок «Источники и диагностика». Он собирает источники и сведения о поиске для всех ответов выбранной беседы. Там можно посмотреть формулировку поискового запроса, если приложение её изменило, дополнительный поиск по истории, исходные оценки и фрагменты, которые вошли в итоговый набор. Источник, найденный только как дополнение к вопросу, помечается отдельно.

## Вкладка «База знаний»

### Загрузка и метаданные

Выберите файл, укажите название, язык и тип источника. Тип можно выбрать как «Официальный» или «Сторонний». Если известны версия, дата публикации, URL и Git-коммит, внесите их. Версия помогает отличать рекомендации для разных выпусков Git, а URL позволяет найти оригинал. Тип источника учитывается инструкцией модели при разборе прямого противоречия между материалами.

Приложение принимает TXT, Markdown, AsciiDoc, HTML и ZIP. Размер одного загружаемого файла — до 20 МиБ. Для текстовых файлов используйте UTF-8 или UTF-16 с маркером кодировки. PDF, изображения и сканы через интерфейс не обрабатываются. В ZIP можно хранить несколько текстовых файлов. Внутри архива дополнительно поддерживаются RST, JSON, JSONL, CSV, TSV, YAML, XML, INI и CFG. Вложенные архивы и картинки пропускаются. Для ZIP установлены ограничения в 3 000 записей, 300 МиБ объявленного распакованного размера и 30 МиБ отобранного текста.

Практичный материал для базы — текст с понятными заголовками и отдельными примерами. Если вы сами готовите инструкцию, выделяйте заголовками задачи, перечисляйте условия применения и размещайте пояснения рядом с командами. Из ZIP лучше убрать сгенерированные файлы и служебный текст, который не должен участвовать в ответах.

### Действия с документом

| Действие | Результат |
| --- | --- |
| Просмотр | Открывает метаданные, SHA-256 и извлечённый текст. Для ZIP видно, к какому файлу относится каждая часть. |
| Чанки | Показывает результаты подготовки и предупреждения. Список разбит на страницы по 20 фрагментов. У каждого видны путь, раздел, число токенов, ID, хеш текста и сам текст. |
| Подготовить и индексировать | Запускает локальную подготовку и запись в поисковый индекс. На экране видны этап, прогресс, итоговое число чанков и учтённые расходы embeddings. |
| Заменить | Открывает форму с текущими метаданными. Выберите новый файл и подтвердите замену. После изменения исходника или значимых для индекса данных заново подготовьте и проиндексируйте документ. |
| Удалить | Удаляет документ и его исходный файл из прикладной базы, исключает его из активного поиска. Очистка векторной коллекции при занятом индексе может быть отложена. Снимки уже выданных ответов остаются в истории. |

Два одинаковых файла обнаруживаются по SHA-256 исходных байтов. Переименование файла или изменение названия в форме не позволяет загрузить тот же оригинал второй раз. При ошибке разбора замены прежний документ сохраняется. Во время фоновой индексации дождитесь результата перед запуском следующей задачи. После прерывания работы сервера запустите подготовку и индексацию заново.

## Вкладка «Тесты RAG»

На вкладке собраны 35 эталонных вопросов. В исходном наборе базы 20 вопросов требуют прямого ответа, 8 — объединения нескольких фрагментов, 7 — корректного сообщения, что сведений недостаточно.

1. Нажмите «Копировать вопрос» рядом с примером.
2. Откройте новую беседу в чате, вставьте вопрос и дождитесь результата. Новая беседа исключает влияние других тестов на формулировку запроса.
3. Вернитесь на вкладку тестов и раскройте «Эталон и критерии». Сравните смысл, условия применения и подтверждающие источники. Дословное совпадение с эталоном не требуется.
4. По ссылке на подтверждающий чанк можно открыть его во вкладке «База знаний». Если после переиндексации эталонная позиция больше не указывает на прежний ID, интерфейс сообщит о несовпадении.

Эталонный набор рассчитан на конкретный снимок двух документов — Pro Git и git status. Если вы развернули чистую копию без этих материалов, содержимое вкладки всё равно видно, но ссылки могут не открываться, а ответы зависеть от вашей базы. Набор предназначен для ручной проверки. Открытие вкладки не запускает модель. [Отчёт о проверке 35 эталонов](rag-evaluation-results.md)

## Вкладка «Настройки»

| Блок | Что настраивается или показывается |
| --- | --- |
| Расходы RouterAI | Известная общая сумма и её разбивка на embeddings и генерацию, число учтённых вызовов и число вызовов без стоимости. Суммы в интерфейсе округляются до целого рубля. |
| Подготовка документов | Выбор обработчика. «Локальный обработчик» выбран по умолчанию. Docling — экспериментальный вариант, доступный после отдельной установки. После смены обработчика заново подготовьте и проиндексируйте документы. |
| Подключение RouterAI | Base URL, API-ключ, модель embeddings, модель генерации и системный промпт. После изменений нажмите «Сохранить настройки». Смена модели embeddings требует переиндексации, чтобы модель документов совпадала с моделью вопроса. |
| Пороги поиска | Отдельные минимальные оценки для Vector и BM25. Значение действует только при включённой галочке соответствующего порога. По умолчанию оба выключены. После смены порогов пересоздавать embeddings не нужно. |
| Проверка подключения | «Проверить подключение» проверяет доступ к API. «Проверить embeddings» создаёт пробный вектор, «Проверить JSON» проверяет структурированный ответ. Две последние операции платные. |
| Журнал операций | До 200 последних событий на экране. В раскрываемой записи видны детали запроса, валидация, ошибки, ID, диагностические данные и источник стоимости, если они были записаны для этой операции. |

Системный промпт — инструкция, по которой модель пишет ответ. Он задаёт язык, отношение к источникам и формат результата. При редактировании сохраняйте требование вернуть JSON со статусом, текстом, списком источников и недостающими сведениями. Слишком строгий порог может убрать подходящие чанки, слишком мягкий — оставить посторонние. Изменяйте настройки по одной и сравнивайте поиск на одном и том же вопросе в новых беседах.

Суммы берутся из ответа RouterAI о стоимости. Подробная запись хранит значение с доступной точностью. При неизвестной стоимости сумма не заменяется нулём. Число «без стоимости» показывает, для скольких учтённых вызовов итог пока неизвестен. Приложение не блокирует запросы по бюджету. Локальный подсчёт токенов, разбиение и поиск в уже сформированном локальном индексе сами по себе не являются платными вызовами. Запросы на создание векторов и вызовы модели могут быть платными.
