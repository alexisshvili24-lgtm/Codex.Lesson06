# Git Support — развёртывание и сопровождение

Для разработчиков и тех, кто устанавливает приложение. Работа в интерфейсе описана в [руководстве пользователя](user-guide.md). Архитектура поиска, промпты и JSON-контракты собраны в [руководстве по реализации RAG](rag-architecture.md).

## Назначение и границы приложения

Git Support — учебный помощник по Git. Он отвечает на вопросы по загруженной документации и показывает конкретные фрагменты, на которые опирается ответ. Пользователь сам загружает и индексирует материалы. Приложение ищет по активному индексу, отправляет найденные фрагменты модели и сохраняет ответ вместе со снимками источников. Команды Git в ответе предназначены для чтения. Приложение не запускает их и не подключается к рабочему репозиторию пользователя.

Приложение поддерживает несколько учебных профилей с входом по никнейму без пароля. Это не подтверждает личность пользователя: любой человек, знающий ник `admin`, получает доступ к его данным и общим настройкам. Поэтому режим предназначен только для учебного стенда и доверенной среды. Для публичного использования нужны HTTPS и отдельная авторизация с подтверждением личности.

Приложение использует один процесс backend и одно общее хранилище SQLite/Qdrant. Чаты, системный промпт, поисковые пороги, ключ RouterAI, журнал и расходы разделены по профилям. Документы, подготовленные чанки, активный индекс, набор эталонов, Base URL, модель генерации и выбранный обработчик общие. Любой вошедший может менять документы и запускать индексацию; расходы при этом относятся к запустившему пользователю и его ключу. Только `admin` меняет общие настройки.

## Зависимости

## Установка на Windows

1. Скопируйте или клонируйте исходники в папку, доступную учётной записи приложения, например `C:\Apps\GitSupport`. В поставку входят `app.py`, `src`, `static`, `migrations`, `alembic.ini`, `requirements.txt` и `run.ps1`. Данные установки и секреты хранятся вне образа и Git. В репозитории папка `data` исключена из Git, поэтому чистая установка начинается без документов, индекса и файла токенизатора.
2. Откройте PowerShell в корне проекта. Проверьте Python, создайте окружение и установите зависимости. Если команда `py` отсутствует, используйте `python` после проверки, что он запускает Python 3.14 x64.

   ~~~powershell
   py -3.14 --version
   py -3.14 -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   .\.venv\Scripts\python.exe -m pip check
   ~~~

3. Поместите `bge-m3-tokenizer.json` в `data\tokenizers`. Его можно перенести из действующей установки. При чистой установке скачайте только файл токенизатора из зафиксированной ревизии BAAI. Для файла, скачанного без изменений, ожидается указанный SHA-256. У уже сохранённой копии с добавленным UTF-8 BOM хеш байтов будет отличаться, приложение читает обе формы. [Файлы BAAI/bge-m3 в зафиксированной ревизии](https://huggingface.co/BAAI/bge-m3/tree/5617a9f61b028005a4858fdac845db406aefb181)

   ~~~powershell
   New-Item -ItemType Directory -Path .\data\tokenizers -Force
   $revision = '5617a9f61b028005a4858fdac845db406aefb181'
   $tokenizer = ".\data\tokenizers\bge-m3-tokenizer.json"
   Invoke-WebRequest "https://huggingface.co/BAAI/bge-m3/resolve/$revision/tokenizer.json" -OutFile $tokenizer
   $expected = '21106b6d7dab2952c1d496fb21d5dc9db75c28ed361a05f5020bbba27810dd08'
   if ((Get-FileHash $tokenizer -Algorithm SHA256).Hash -ne $expected) {
       throw 'SHA-256 файла токенизатора не совпал.'
   }
   ~~~

4. Запустите `.\run.ps1` и откройте [Git Support](http://127.0.0.1:8025/). При старте приложение применяет миграции Alembic до текущей версии схемы и создаёт SQLite при необходимости. Скрипт проверяет порт, открывает браузер и записывает stdout и stderr в `logs`. Для штатной остановки нажмите Enter в окне скрипта после завершения текущей индексации.
5. Войдите под ником `admin` для унаследованного профиля существующей установки или введите новый ник для чистого профиля. Настройте ключ RouterAI в разделе ниже. Затем загрузите небольшой текстовый документ, нажмите «Подготовить и индексировать», дождитесь результата и задайте вопрос с известным ответом из этого текста.

## Профили, миграция и секреты

При первом старте новой версии приложение применяет Alembic-миграции до открытия HTTP-запросов, создаёт (или сохраняет) профиль `admin`, затем переносит прежний ключ `ROUTERAI_API_KEY` в `ROUTERAI_API_KEY_USER_1` в `.env`. Старое имя ключа удаляется. Перенос синхронизируется файловой блокировкой и повторяем: если процесс завершится после записи нового ключа, повторный старт завершит перенос, не создавая второго admin и не перезаписывая уже сохранённый ключ. Если обязательная миграция завершилась ошибкой, сервер не поднимется.

Перед обновлением действующей установки остановите приложение и сохраните **всю** папку постоянных данных (`/app/data` в контейнере: SQLite, Qdrant, `.env`, загруженные документы и токенизатор). Сверьте, что резервная копия не пустая и читается. После обновления запустите приложение и проверьте `/health`, вход как `admin`, прежний чат, список документов и активный индекс. Если перенос прервался или данные выглядят неверно: остановите приложение, сохраните неудачную новую папку данных отдельно, восстановите целую резервную копию и повторите запуск. Не восстанавливайте только SQLite или только `.env`: между ними хранится связь ключа и версии. Не запускайте Alembic downgrade для отката опубликованной базы.

В чистой установке профиль `admin` появляется при первом входе; старого ключа нет, пока он не будет введён в настройках. Другой ник создаёт отдельный профиль без ключа и истории. Вход повторно под тем же нормализованным ником открывает прежний профиль. Ник нормализуется по Unicode NFC и `casefold`; пробелы по краям убираются. Допустимы 1–32 буквы, цифры, дефис и подчёркивание.

Ключи пользователей не лежат в SQLite: они находятся в `.env` как `ROUTERAI_API_KEY_USER_<id>`. Например, ключ пользователя с внутренним ID 2 будет `ROUTERAI_API_KEY_USER_2`. Интерфейс возвращает только признак `key_configured`; для смены ключа введите новый, пустое поле сохраняет прежний. Закройте `.env` правами ОС и включите его в резервную копию. Не копируйте реальные значения в логи, issue, образ или тесты. Файл `.env.lock` используется для синхронизации изменений и также не должен попадать в Git.

Сессия выдаётся в `HttpOnly`, `SameSite=Lax` cookie, а в SQLite сохраняется только SHA-256 хеш случайного токена. Срок действия — 30 дней; выход удаляет серверную сессию и cookie. При HTTPS cookie получает флаг `Secure`; при TLS-терминации на reverse proxy проверьте, что ASGI-приложение корректно получает внешний HTTPS scheme от доверенного proxy. В текущем публичном HTTP сценарии cookie не может иметь `Secure`, поэтому не передавайте через него реальные секреты.

`ROUTERAI_ALLOWED_BASE_URLS` — конфигурация установки: список разрешённых HTTPS Base URL через запятую. По умолчанию разрешён только RouterAI. Изменять это значение должен оператор установки; перед каждым запросом сервер сверяет Base URL с allowlist, а перенаправления отклоняются, чтобы не переслать пользовательский ключ другому узлу. Только профиль `admin` может изменить общий Base URL и модель генерации. Модель embeddings остаётся общей и неизменяемой, так как существующий Qdrant-индекс создан для `baai/bge-m3`.

Если PowerShell на сервере запрещает запуск скрипта, используйте прямой запуск Uvicorn из следующего раздела.

## Секреты и настройки

1. Каждый профиль вводит собственный API-ключ в «Настройки» → «Подключение RouterAI». Ключ записывается в `.env` в корне проекта под именем `ROUTERAI_API_KEY_USER_<id>`. Интерфейс показывает только наличие ключа. Пустое поле при сохранении оставляет прежний ключ. Платные вызовы и индексация используют ключ текущего профиля; если ключ не задан, платный запрос завершается понятной ошибкой.
2. При установке без браузера можно создать `.env` вручную. Пример содержит заполнитель.

   ~~~dotenv
   ROUTERAI_API_KEY_USER_1=replace-with-admin-key
   ~~~

   Код читает ключи именно из файла `.env`. В реальной установке предпочтительно сохранять их через интерфейс, чтобы обновлялась версия ключа. В Git ключ и файл `.env` не передаются. Ограничьте доступ к файлу средствами ОС. Учётной записи процесса нужны права на запись в `.env`, если ключ меняется через интерфейс.
3. По умолчанию адрес API — `https://routerai.ru/api/v1`, модель embeddings — `baai/bge-m3`, модель генерации — `deepseek/deepseek-v4.1-flash-1017`. Значения можно изменить в настройках. Для основного сценария используйте RouterAI с доступом к выбранным моделям. Совместимый endpoint должен поддерживать `/models`, `/embeddings`, структурированные ответы `/chat/completions` и используемый в проекте запрос стоимости `/generation?id=…`. Перед вводом ключа проверьте, что Base URL указывает на доверенный endpoint провайдера, которому принадлежит ключ.
4. Запустите «Проверить подключение», затем «Проверить embeddings» и «Проверить JSON». Последние две проверки выполняют платные запросы. Положительная проверка подключения сама по себе не подтверждает доступ к обеим моделям.
5. Base URL, идентификаторы моделей, промпт, пороги и выбранный обработчик сохраняются в SQLite. `DATABASE_URL` читается из окружения процесса, затем из `.env`. По умолчанию используется `data/app.sqlite3`. Для нестандартного расположения SQLite задайте, например, `DATABASE_URL=sqlite:///C:/GitSupportData/app.sqlite3`. Путь Qdrant задаётся переменной **окружения процесса** `QDRANT_PATH`, по умолчанию это `data/qdrant`. Путь токенизатора фиксирован относительно корня проекта.

При переносе согласованного снимка рабочей базы сохраняются её настройки и системный промпт. В итоговой учебной установке сохранённый промпт совпадает с `src/default_prompt.txt`, оба порога выключены, а `local` используется как встроенное значение по умолчанию. Чистая установка берёт те же базовый промпт и режим порогов из исходников. Настройки разбиения запросов, число чанков и служебный промпт планировщика входят в код приложения.

Тексты выбранных для индексации чанков, поисковые запросы и выдержки из беседы отправляются в RouterAI. Перед загрузкой материалов и вводом вопросов проверьте, что эти данные допустимо передавать провайдеру. В журнале приложения сохраняются запросы, ответы и фрагменты документов. Даже при маскировании API-ключа журнал и резервные копии нужно защищать как рабочие данные.

## Запуск на собственном сервере

На Windows-хосте выполните шаги установки. Для длительной работы используйте прямой запуск без открытия браузера. Порт можно изменить, согласовав его с командой туннеля.

~~~powershell
Set-Location C:\Apps\GitSupport
.\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8025 --workers 1
~~~

Для автозапуска создайте задачу Windows Task Scheduler от отдельной учётной записи с доступом к папке проекта и исходящим HTTPS. Укажите триггер «При запуске системы», абсолютный путь к `C:\Apps\GitSupport\.venv\Scripts\python.exe`, аргументы `-m uvicorn app:app --host 127.0.0.1 --port 8025 --workers 1` и рабочую папку `C:\Apps\GitSupport`. Настройте сбор stdout/stderr средствами запуска. Папка `logs` заполняется автоматически при использовании `run.ps1`, прямой запуск пишет в консоль. Проверьте старт и остановку задачи вручную, затем проверьте восстановление после перезагрузки. Не запускайте одновременно задачу и `run.ps1` на одном наборе данных. Локальный Qdrant, блокировки и статус фоновой индексации рассчитаны на один процесс.

Для удалённого доступа установите или включите OpenSSH Server на хосте и разрешите SSH только доверенным пользователям и сетям. Проверьте, что разрешено локальное перенаправление портов. На рабочем компьютере выполните, заменив имя пользователя и сервера. [Настройка OpenSSH в Windows](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh_install_firstuse)

~~~powershell
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:18025:127.0.0.1:8025 user@server.example.com
~~~

Пока туннель открыт, перейдите на [локальный адрес туннеля](http://127.0.0.1:18025/) в браузере. Это веб-интерфейс удалённой установки. Порт приложения на сервере остаётся привязан к loopback, а трафик до сервера идёт внутри SSH. При занятом порте `18025` выберите другой локальный порт и поменяйте адрес браузера. Если браузер сообщает об отказе в соединении, проверьте Uvicorn на самом сервере. Успешное открытие SSH-туннеля не подтверждает, что приложение запущено. [Руководство OpenSSH по локальному перенаправлению](https://man.openbsd.org/ssh)

### Домен и публичный хостинг

Копирование `static` на обычный статический хостинг не развернёт приложение. Браузеру нужны API, SQLite и Qdrant Local на стороне сервера. Код проверяет `Host` и соответствие `Origin`. С произвольным доменом текущий backend возвращает HTTP 403. Эта проверка не является аутентификацией.

Если адрес на домене обязателен, выделите это в отдельную задачу развёртывания. Минимум для публичного доступа — HTTPS, настройка явного списка допустимых хостов и origin, тест запросов с другого origin и ограничение доступа к backend на уровне сети. Шлюз должен проверять исходный браузерный origin до подмены заголовков, если такая подмена нужна. Вход по нику в текущей учебной версии не является аутентификацией: любой посетитель может занять любой ник, в том числе `admin`. Не публикуйте проект как защищённый сервис и не передавайте через HTTP реальные ключи. Публичный сценарий требует отдельно разработать полноценное подтверждение личности.

## Хранение, резервное копирование и обновление

| Объект | Что в нём хранится |
| --- | --- |
| `.env` | Ключ RouterAI и необязательный путь SQLite. |
| SQLite | `settings`, `documents` с оригиналом и извлечённым текстом, `chunk_runs` и `prepared_chunks`, `index_generations` и `index_pending`, `events` с журналом, расходами и историческими снимками, `chat_conversations` и `chat_turns`. |
| `data/qdrant` или `QDRANT_PATH` | Коллекции активных и временных поколений, векторы и payload чанков. |
| `data/tokenizers/bge-m3-tokenizer.json` | Локальный токенизатор. |
| `logs` | Файлы консоли запуска через PowerShell. Рабочие события приложения хранятся в SQLite. |

Перед резервной копией дождитесь завершения индексации и остановите приложение. Скопируйте SQLite вместе с её сопутствующими файлами, если они остались, каталог Qdrant целиком и токенизатор в один согласованный снимок. Для SQLite включён режим WAL. Копирование одного файла `app.sqlite3` у работающего экземпляра может пропустить записи. Ключ сохраните отдельно в защищённом хранилище, либо выпустите новый при восстановлении. Если изменены пути, копируйте данные по фактическим путям.

Для восстановления остановите приложение, верните согласованный снимок, проверьте пути и права доступа и запустите сервер. Убедитесь, что открываются старые беседы, документы видны в индексе и новый вопрос находит источники. Если осталась только SQLite, сохранённые документы можно вручную проиндексировать заново. Это создаст новые платные embeddings. Вопросы, старые ответы и их снимки источников хранятся в SQLite.

Перед обновлением снимите резервную копию, перенесите новый код без перезаписи `.env` и данных, установите зависимости и перезапустите сервер. Текущая миграция — `0006`. Если требуется откат, восстановите прежнюю версию кода и соответствующий снимок данных вместе. Если поменялись исходник, выбранный обработчик, совместимость токенизации или embedding-модель, проверьте актуальность и повторите индексацию нужных документов. Смена модели генерации и промпта сама по себе не требует пересоздания векторов.

| Узел | Файлы и назначение |

Для Docling создайте отдельное окружение и установите зависимости из [файла версий Docling](../tests/docling_lab/requirements.lock.txt).

~~~powershell
.\.venv\Scripts\python.exe -m venv .venv-docling
.\.venv-docling\Scripts\python.exe -m pip install -r tests\docling_lab\requirements.lock.txt
~~~

После установки выберите плагин в интерфейсе и заново подготовьте документы. Приложение также распознаёт экспериментальное окружение `.tmp/docling-lab`, если оно есть. Docling запускается отдельным процессом в автономном режиме, а форматы, для которых он не используется, обрабатывает локальный алгоритм с предупреждением. Разбор AsciiDoc этим плагином может завершиться ошибкой. Контракт стороннего плагина и имя точки входа `git_support.chunk_plugins` описаны в [README](../README.md).

Запуск тестов из корня проекта:

~~~powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -t . -v
~~~

Тесты используют изолированные данные. Для ручной проверки API на копии задайте отдельные `DATABASE_URL`, `QDRANT_PATH` и порт. Обычные проверки в интерфейсе, создание векторов и ответы через RouterAI могут расходовать средства. В диагностике ищите одну операцию по времени и идентификатору запроса. Вложенные вызовы поиска и генерации связаны с запросом через `group_id`. Проверьте реальные ответы по трём категориям из вкладки «Тесты RAG» и отдельно проверьте уточнение в существующей беседе.

### Если запуск или поиск не работает

| Симптом | Что проверить |
| --- | --- |
| Порт занят | Найдите уже запущенный экземпляр или запустите Uvicorn на другом порту с отдельными данными. |
| Сайт не открывается | Проверьте процесс, адрес loopback, порт, журнал запуска и ошибки миграций. При SSH проверьте обе стороны туннеля. |
| HTTP 403 при открытии по домену | Проверьте модель доступа. Штатный маршрут использует локальный адрес или SSH. |
| Ошибка токенизатора или разбора | Проверьте путь, контрольную сумму скачанного файла, расширение, кодировку, структуру и предупреждения плагина. |
| Индекс занят или работа прервана | Дождитесь завершения, откройте журнал и повторите индексацию после остановки прерванной работы. Не открывайте каталог Qdrant вторым процессом. |
| В индексе нет документов | Проверьте число активных чанков. После смены embedding-модели или плагина заново подготовьте и проиндексируйте документы. |
| Не прошла генерация | Проверьте ключ, Base URL, доступность модели и тест JSON. Если проблема только в одном вопросе, проверьте журнал и результат валидации. |
| Частичный ответ при наличии источника | Проверьте основной запрос, пары формулировок, пороги и итоговую выборку до десяти чанков. Поля search_groups, evidence_types и diagnostics.query_results показывают формулировки, нужный тип материала и найденные идентификаторы. |

## Что из исходного ТЗ не вошло в итоговую разработку

Сравнение с [исходным ТЗ](TZ.md). Базовый учебный RAG-проект был принят владельцем как завершённый; многопользовательский режим реализуется отдельно по [ТЗ профилей](TZ-multiuser.md).

| Требование | Итог |
| --- | --- |
| § 3, § 15–16, этап 6А и критерии 21–22. Локальный голосовой ввод Vosk Small RU 0.22 | Не реализован. В чате только текстовый ввод. Нет захвата аудио, распознавания, исправления распознанного текста и журнала STT. |
| § 5, часть § 3.3 и критерий 20. Бюджет 80 ₽, остаток и блокировка новых платных вызовов | По решению владельца оставлен учёт фактических расходов без бюджетного порога. Неизвестная стоимость помечается отдельно и не останавливает вызовы. |
| § 7.2. Загрузка и обработка PDF с извлекаемым текстом | Исключена по решению владельца. Экспериментальные скрипты и зависимость pypdf не означают поддержку PDF в рабочем интерфейсе. Вместо PDF в итоговую поставку включён ZIP с текстовыми файлами. OCR изначально был вне ТЗ. |
| § 8.2. Пять абзацев, шаг четыре, перекрытие одного абзаца | По согласованию заменено структурным алгоритмом с ориентиром по токенам и перекрытием целыми предложениями либо цельным смысловым блоком. Размер и число абзацев переменные. |
| § 6.1. Токены и полные служебные данные для всех запросов | В журнале генерации и проверок токены доступны в `usage`, если провайдер их вернул. Рабочие пакетные embeddings логируют число текстов, идентификатор, время, стоимость и ошибки, без полного ответа с векторами и отдельной записи `usage`. Итоговая строка журнала индексации показывает статус, число чанков и расходы, без отдельной общей сводки по нескольким документам. |
| Этап 7 и критерий 23. Итоговый прогон вопросов | Есть 35 эталонных вопросов и [отчёт о полном прогоне на финальной версии](rag-evaluation-results.md), включая англоязычную справку и вопросы по-русски. Проверены как ответы, так и отбор источников. Сценарии с контекстом беседы проверялись отдельно. |

Дополнения к исходному ТЗ — архив независимых вопросов, отдельные беседы с накопленным резюме, вспомогательный поиск по контексту, вкладка «Тесты RAG» и выбор локального обработчика документов. Поддержка публичного сайта, ролей и многопользовательского режима изначально не требовалась.
