# Git Support

Локальное учебное приложение поддержки Git. Оно индексирует загруженную документацию и отвечает на вопросы с помощью гибридного поиска и RAG, показывая подтверждающие фрагменты.

- [Развёртывание и сопровождение](docs/developer-guide.md)
- [Руководство пользователя](docs/user-guide.md)
- [Реализация RAG от файла до ответа](docs/rag-architecture.md)
- [Результаты проверки на 35 эталонах](docs/rag-evaluation-results.md)

## Запуск в PowerShell

Требуется Python 3.14. В каталоге проекта выполните:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\run.ps1
```

Откройте http://127.0.0.1:8025. Для остановки нажмите Enter в окне запуска. При ошибке окно ожидает Enter; журналы сервера находятся в папке logs. Приложение доступно только на этом компьютере. При первом запуске Alembic создаёт локальную базу в data; DATABASE_URL можно задать в .env.

## Проверка настроек

В разделе «Настройки» введите API-ключ RouterAI и сохраните настройки. Ключ сохраняется в локальном .env и не отображается повторно; пустое поле сохраняет прежний ключ. Проверка подключения запрашивает список моделей. Проверки embeddings и JSON отправляют реальные платные запросы. Стоимость отображается только если получена от провайдера; неизвестная стоимость отдельно отмечается и не входит в учтённую сумму. Лимит расходов отсутствует. Результаты и сведения для диагностики доступны в журнале. Настройки можно проверить после перезапуска.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -t . -v
```
## База знаний

В разделе «База знаний» выберите файл, укажите название, язык и тип источника; остальные метаданные можно оставить пустыми. Поддерживаются TXT, Markdown, AsciiDoc (в том числе .asc), HTML размером до 20 МБ. Загрузка новых PDF отключена. Текстовые файлы должны быть в UTF-8 или UTF-16. OCR не предусмотрен. После загрузки выберите «Просмотр», чтобы увидеть метаданные, SHA-256 и извлечённый текст. Замена и удаление требуют подтверждения. При ошибке разбора прежний документ остаётся без изменений. Повторная загрузка того же файла определяется по SHA-256 и отклоняется, даже если название изменено. Оригинал и извлечённый текст сохраняются в SQLite; подготовка чанков запускается вручную.

После обновления проекта установите зависимости из requirements.txt и перезапустите приложение. При запуске Alembic создаст таблицу документов; существующие настройки и журнал сохранятся.
## ZIP с текстовыми файлами

ZIP до 20 МБ обрабатывается без распаковки на диск. Текстовые файлы поддерживаемых расширений читаются отдельно с сохранением путей; директивы `include::` не выполняются. Архив может содержать TXT, Markdown, AsciiDoc, HTML, RST, JSON, CSV, TSV, YAML, XML, INI и CFG в UTF-8/UTF-16. Изображения и другие неподдерживаемые файлы пропускаются. Файлы с неверной кодировкой или опасными путями приводят к отказу загрузки. Файл списка участников Pro Git исключается по решению владельца. Оригинальный ZIP сохраняется целиком. Файлы архива разбиваются на чанки независимо; разметка и повторяющиеся материалы требуют проверки.
## Подготовка чанков: этап 3

Для документа в «Базе знаний» нажмите «Подготовить и индексировать», затем «Чанки» для просмотра текста, источника, хеша и числа токенов. Показываются предупреждения и статистика; результаты экспериментальные и требуют ручной проверки. Подготовка локальная, без embeddings и платных запросов. Новый запуск создаёт отдельный результат; если документ заменён или его метаданные изменились, старый результат не показывается для новой версии. PDF не обрабатываются.

Необходим локальный файл токенизатора `data/tokenizers/bge-m3-tokenizer.json`. В текущем окружении он уже скачан; при переносе проекта сохраните его вместе с данными. При отсутствии файла приложение сообщит об ошибке. Миграция 0003 создаёт отдельные таблицы чанков при запуске сервера.
Ориентир размера — 500 токенов BGE-M3, обычно 400–600; по возможности сохраняются абзацы, списки, команды и примеры. Перекрытие выбирается целыми предложениями; между разделами и файлами его нет. Команды и списки сохраняются целыми смысловыми блоками, поэтому при их перекрытии может повториться весь блок. Список, превышающий предел модели, делится по пунктам. Если отдельный пункт, команда или пример слишком велики и безопасная граница не найдена, подготовка останавливается с ошибкой. URL относится ко всему документу; связи файлов архива автоматически не восстанавливаются. В архив могут входить служебные текстовые файлы и повторяющиеся материалы; проверяйте предупреждения и содержимое чанков.

## Плагины подготовки документов

По умолчанию используется встроенный локальный плагин. Выберите обработчик в разделе «Настройки» → «Подготовка документов» и нажмите «Сохранить плагин»: изменение действует сразу и сохраняется между запусками. В списке также отображаются зарегистрированные дополнительные плагины. Результаты, подготовленные другим плагином или предыдущей версией алгоритма, не выдаются как актуальные; после смены повторно запустите подготовку. В чанке записано имя плагина. PDF по-прежнему не принимается.

Docling устанавливается отдельно от окружения приложения, чтобы его зависимости не меняли основные версии. На Windows в PowerShell, из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m venv .venv-docling
.\.venv-docling\Scripts\python.exe -m pip install -r tests\docling_lab\requirements.lock.txt
```

После установки выберите Docling в настройках сайта. Приложение автоматически ищет отдельное окружение в `.venv-docling`; в текущем проекте также доступно экспериментальное окружение `.tmp/docling-lab`. Если окружения нет, Docling показывается как не установленный. Docling запускается отдельным процессом в автономном режиме; для неподдерживаемых им текстовых форматов используется локальный обработчик с предупреждением. Известны ошибки Docling на реальных AsciiDoc; результат требует проверки, PDF не включается этим переключателем. Выбор не устанавливает зависимости автоматически и не загружает модели.

Другой установленный Python-пакет может зарегистрировать точку входа `git_support.chunk_plugins` с именем плагина и фабрикой без аргументов. Созданный объект предоставляет `prepare_file(path, text, count)` и возвращает пару `(chunks, warnings)`: список объектов `src.chunking.Chunk` и список текстовых предупреждений. Общий конвейер по-прежнему проверяет ZIP, разделяет файлы, присваивает источники, идентификаторы и сохраняет результаты. Выбираются только явно указанные имена; совпадающие имена отклоняются.

Локальный плагин при подготовке AsciiDoc удаляет из поискового текста служебные якоря, индексные пометки и отдельные директивы include; команды в блоках кода сохраняются. Файлы с двойным расширением, например `.adoc.txt`, обрабатываются как AsciiDoc. Директивы include не раскрываются: приложение предупреждает об этом, а подключаемые файлы нужно загрузить отдельно. Изображения и перекрёстные ссылки автоматически не раскрываются. После обновления алгоритма перезапустите сервер и заново подготовьте чанки: старые результаты остаются в базе, но не считаются актуальными.

Подготовка чанков и индексация запускаются вместе вручную кнопкой «Подготовить и индексировать». Приложение отправляет тексты в RouterAI, сохраняет векторы и метаданные в локальный Qdrant, показывает прогресс и учтённые расходы. Повторный запуск для неизменённых чанков и модели использует сохранённый индекс. При смене модели или содержимого требуется повторная индексация. Если сервер остановился во время индексации, сайт сообщит о прерывании и предложит запустить её повторно; незавершённые коллекции будут очищены.

## Тесты RAG

Вкладка «Тесты RAG» содержит 35 вопросов по снимку индекса Pro Git и git status. Скопируйте вопрос, задайте его во вкладке «Чат», затем откройте «Эталон и критерии». Сравнивайте обязательные пункты и опору на источники, а не дословное совпадение. Из них 20 проверяют прямой ответ, 8 требуют объединить несколько фрагментов, а для 7 ожидается сообщение о недостатке сведений в базе.

Набор хранится в `static/rag-evaluation.json`. Ссылки привязаны к документу, позиции и идентификатору чанка. После замены источника или изменения чанков перепроверьте эталоны и обновите ссылки.


## Гибридный поиск и RAG-чат

Запустите `run.ps1`, откройте «Чат» и нажмите «Новая беседа». Первый вопрос даёт беседе название. Продолжайте уточнения в той же беседе или начните новую для отдельной темы. Предыдущие независимые вопросы доступны в «Архиве вопросов».

Один вызов модели готовит поисковые запросы в строгом JSON. Для каждой самостоятельной части вопроса он возвращает основную и переформулированную версию. В беседе этот же вызов обновляет резюме по последней паре реплик и может предложить один вспомогательный запрос по явно упомянутому контексту. Модель ответа получает исходный вопрос и отобранные фрагменты. Для каждого независимого вопроса из «Тестов RAG» начинайте новую беседу.

Цитата `[S1]` открывает сохранённый фрагмент. Блок «Источники и диагностика» под перепиской собирает источники всех ответов и показывает оценки, пороги, причины отбора и формулировки основного и дополнительного запросов, если они выполнялись.

Поиск получает embeddings всех формулировок одним пакетом. По каждой основной формулировке Vector и BM25 дают до 15 кандидатов, которые объединяются через RRF с учётом порогов. В ответ идут до 10 уникальных фрагментов. Первое место получает лучший результат по текущему вопросу. Для каждой части локальная пересортировка учитывает, нужен ли для ответа пример команды, фрагмент вывода или объяснение правила. Один вспомогательный фрагмент из истории беседы может завершать список. Длинные флаги Git сопоставляются целиком. При пустой выдаче модель ответа не вызывается. Вызовы RouterAI и их стоимость регистрируются в журнале. [Итоговый и исторический прогоны на 35 вопросах](docs/rag-evaluation-results.md).

## Публичный HTTP-доступ

Приложение разрешает Host 179.254.162.130 и локальные адреса. Дополнительные адреса задаются через APP_ALLOWED_HOSTS через запятую. При публичном доступе функции, включая настройки и платные запросы RouterAI, доступны без авторизации. Подробности — в docs/container-deployment.md.
